## 1. 화면 목적

상담원이 키워드·가격 범위·최소 침실 수로 매물을 **실시간**(버튼 없이) 좁히고 한 번에 초기화한다. 필터 항목·입력 단위(원)·경계 규칙·예외 입력 동작을 고객과 확인한다.

## 2. Wireframe

```
┌ filter-panel ───────────────────┐
│ 검색 필터                        │
│ 키워드                           │
│ [ 매물명 또는 도시          🔍 ] │ ← filter-keyword (type=search)
│ 최소 가격 ⓘ 원 단위 전체 금액     │
│ [                            ]  │ ← filter-min-price (number, min=0)
│ 최대 가격 ⓘ                      │
│ [                            ]  │ ← filter-max-price (number, min=0)
│ 최소 침실 수                     │
│ [ 전체                     ▼ ]  │ ← filter-min-bedrooms (전체 ~ 5개 이상)
│ (CK-03 확정 시 filter-price-error)│
│ [ ⟳ 초기화 ]                     │ ← filter-reset
└─────────────────────────────────┘
 입력 → 300ms 디바운스 → 'filterchange' → 부모가 filterProperties() → 목록·건수 갱신
 "판매완료 제외" 류 상태 옵션 없음 (D-17)
```

## 3. 구현 범위 (정적 데이터)

| 항목 | 목업 구현 | 본 개발(WI-1.004)에서 교체 |
|---|---|---|
| 컴포넌트 | `lwc/propertyFilter` (라벨·testid·선택지 WI-1.004 §5.4 와 동일) | 동일 이름 승계 |
| 발행 | 300ms 디바운스 → CustomEvent `filterchange` `{keyword, minPrice, maxPrice, minBedrooms}` | LMS `PropertyFilter__c` (같은 페이로드) |
| 필터 로직 | `c/propertyUtils.filterProperties` (클라이언트) — 키워드 trim 후 Name·City__c 부분 일치(대소문자 무시, 주소 제외), 가격 경계 포함, 침실 이상, 상태 제외 없음 | Apex `Database.queryWithBinds(..., USER_MODE)` |
| 초기화 | 즉시 반영, 입력값·오류 표시 해제, 침실 `전체` | 동일 |
| 음수 | `min=0` → `reportValidity()` 실패 시 반영 안 함 | 동일 |
| min > max | **미구현**(그대로 0건) — CK-03 결정 대기 | 결정에 따라 `filter-price-error` |

## 4. 확인 포인트

- CP-08 필터 항목 4종·입력 방식(원 단위 숫자, 예: `1000000000`)·즉시 반영 (CK-02)
- CP-09 최소 > 최대 입력 시 동작 선택 (CK-03)
- CP-10 공백 키워드 = 조건 없음 (CK-04)
- CP-06 상태 필터를 추가로 원하는가 (CK-15)
- 가격 입력 편의(억 단위 선택지·천 단위 쉼표 입력 등) 요구 여부 → 있으면 ADD
